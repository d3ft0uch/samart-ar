# WebAR-прототип для выставки

Два сценария посетителя:
1. **Один QR на зал** → `index.html` → сразу AR-режим, камера узнаёт зоны по фото и накладывает 3D-объекты.
2. **QR у работы** → `viewer.html?id=N` → 3D-модель + кнопка «Посмотреть в зале (AR)».

Без приложений, без VPN, всё раздаётся как статика.

## Структура

```
samart-ar/
├── index.html       AR-зал по фото-зонам (MindAR image tracking) — вход для посетителя
├── admin.html       служебная страница: QR на зал + QR отдельных работ (для печати)
├── viewer.html      персональная страница работы (viewer.html?id=1)
├── works.js         каталог: WORKS (для viewer) + ROOM_CONFIG (для index.html)
├── lib/             локальные библиотеки, без CDN
│   ├── model-viewer.min.js
│   ├── aframe.min.js
│   └── mindar-image-aframe.prod.js
├── models/          GLB для работ + USDZ для iOS AR Quick Look
├── targets/
│   └── room.mind    скомпилированные image-таргеты для AR-зала
├── images/          исходные фото зон (не деплоятся; source для компилятора)
└── tools/           dev-инструменты (не деплоятся)
    ├── compile-room.html   локальный компилятор фото → room.mind (UI)
    ├── compile-room.sh     обёртка: одна команда → пересобрать room.mind
    ├── fbx_to_glb.py       Blender-скрипт: FBX → сжатый GLB (+ опц. USDZ)
    └── fbx_inspect.py      Blender-скрипт: краткий отчёт по FBX
```

Печать QR идёт с `admin.html`. Посетителю даётся только QR на `index.html` (это и есть «Общий QR на зал»).

## Запуск на localhost

```bash
cd samart-ar
python3 -m http.server 8000
```

Открой http://localhost:8000 — список работ; http://localhost:8000/viewer.html?id=1 — просмотр.

## Проверка с телефона

1. Комп и телефон в одной Wi-Fi-сети.
2. Узнай IP компа (`ip a` / `ipconfig`), открой на телефоне `http://<IP>:8000/viewer.html?id=1`.
3. 3D-просмотр (крутить пальцем) заработает сразу. Кнопка AR по http может
   не появиться — WebXR требует HTTPS. Для полноценного AR-теста с телефона:
   - самый простой путь: залить на любой статик-хостинг с HTTPS
     (GitHub Pages: push в репозиторий → Settings → Pages), или
   - локальный HTTPS: `npx serve --ssl-cert ...` с самоподписанным сертификатом
     (телефон будет ругаться на сертификат — можно принять вручную).

## Добавить работу

1. Экспорт из Blender: File → Export → glTF 2.0, формат **glTF Binary (.glb)**.
2. Если файл больше ~5–10 МБ:
   `npx @gltf-transform/cli optimize work2.glb work2_opt.glb --texture-compress webp`
3. Положи в `models/`, добавь запись в `works.js`.
4. QR для печати появится сам на index.html.

## FBX → сжатый GLB

Если тебе прислали тяжёлый FBX (например, 100+ МБ с текстурами 4К) —
конвертнёшь его через локальный Blender:

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b \
  -P tools/fbx_to_glb.py -- \
  --in обжект.fbx \
  --out models/обжект.glb \
  --usdz models/обжект.usdz \
  --decimate 0.2 --tex 1024
```

- `--decimate 0.2` — оставить 20% треугольников (крутить от 0.1 до 0.5,
  смотря насколько модель детализирована).
- `--tex 1024` — максимальная сторона текстуры, px (для WebAR 1024 хватает
  с запасом; для очень крупных объектов можно 2048).
- GLB получает Draco-сжатие геометрии и WebP-текстуры автоматически.
- `--usdz ...` опционален. USDZ нужен для **iOS AR Quick Look**
  (кнопка «Посмотреть в зале (AR)» на iPhone). USDZ не поддерживает Draco
  и хранит текстуры как PNG, поэтому файл получается **заметно тяжелее GLB**
  (десятки МБ вместо единиц). Лимит iOS Quick Look — ~25 МБ. Если не влезает —
  уменьши `--tex` до 512.

Проверить, что внутри исходника (сколько мешей/текстур), можно скриптом
`tools/fbx_inspect.py` — та же команда, но без `--out/--usdz/--decimate/--tex`.

## index.html (AR-зал) — AR по фото зон

Один общий QR на зал (см. блок «Общий QR на зал» на `index.html`).
Каждая «зона» — это заранее выбранное фото (картина, фрагмент стены,
табличка), которое камера узнаёт и рядом появляется 3D-объект.

### Как повесить зоны

- Фото должно висеть на уровне глаз, без бликов и не за стеклом.
- Свет ровный, без резких теней. Резкие тени = плохая узнаваемость.
- Хорошо трекаются картины/постеры с большим количеством нерегулярных
  контрастных деталей по всей площади. Плохо — почти однотонные плоскости,
  зеркала, регулярные геометрические паттерны, тексты крупным шрифтом.
- Минимальный размер по короткой стороне: ~20 см (чем меньше, тем ближе
  придётся подходить с камерой).

### Как собрать `targets/room.mind`

**Автоматически** (одна команда):

```bash
tools/compile-room.sh images/img1.JPG images/img2.JPG images/img3.JPG
```

Скрипт поднимет локальный http-сервер, откроет браузер, дождётся скачивания
`room.mind` в `~/Downloads/` и перенесёт в `targets/room.mind`. Занимает ~30 сек.
Порядок картинок = порядок `ROOM_CONFIG.spots` в `works.js` (первое фото → `spots[0]`).

Эквивалентно: `npm run compile:room` (пути картинок вшиты в `package.json`).

**Вручную**, если хочется контролировать порядок в UI:

1. `python3 -m http.server 8000`, открой http://localhost:8000/tools/compile-index.html (AR-зал).
2. Перетащи фото; при необходимости переупорядочь карточки drag'n'drop.
3. Нажми «Скомпилировать» → сохрани `room.mind` в `targets/room.mind`.

**Альтернатива** — онлайн-компилятор MindAR:
https://hiukim.github.io/mind-ar-js-doc/tools/compile
(тот же принцип, порядок картинок = порядок spots).

### Как подгонять смещения объектов

В `works.js.ROOM_CONFIG.spots` у каждого спота:

- `model` — путь к GLB.
- `scale` — три числа "sx sy sz". Единица = ширина маркера (например,
  если фото шириной 40 см, то `scale: "0.5 0.5 0.5"` даёт объект ~20 см).
- `position` — "x y z" относительно центра фото. X вправо, Y вверх,
  Z вперёд от плоскости фото к камере. Единица та же.
  Пример: `"0 -1.2 0"` — объект стоит на полу под маркером,
  висящим на уровне глаз.
- `rotation` — "rx ry rz" в градусах.

Правки в `works.js` подхватываются сразу — обновить страницу и посмотреть.

### Если `targets/room.mind` не найден

`index.html (AR-зал)` покажет вежливое сообщение с подсказкой, а не чёрный экран.

## iOS Quick Look (по желанию)

На айфонах кнопка AR использует Quick Look, которому нужен `.usdz`.
Без него на iOS остаётся обычный 3D-просмотр — это нормальная деградация.
Если хочется AR и на iOS: Blender умеет экспорт в USD (File → Export →
Universal Scene Description, расширение поставить `.usdz`), либо конвертация
GLB → USDZ через Reality Converter (macOS). Файл кладёшь рядом с GLB и
прописываешь поле `usdz` в `works.js`.

## Продакшн

Любой статик-хостинг с HTTPS. Никакого бэкенда нет, внешних CDN нет —
всё лежит в этой папке (кроме предпросмотра QR на index.html, который
ходит на api.qrserver.com; для печати можно сгенерировать QR любым
офлайн-генератором на те же ссылки).

## Деплой на GitHub Pages

```bash
cd samart-ar
git init
git add -A
git commit -m "webar exhibition"
git branch -M main
git remote add origin git@github.com:ВАШ_ЛОГИН/samart-ar.git
git push -u origin main
```

Затем на GitHub: репозиторий → Settings → Pages → Source: **Deploy from a branch**,
Branch: **main**, папка **/ (root)** → Save. Через минуту-две сайт живой:

- https://ВАШ_ЛОГИН.github.io/samart-ar/ — служебная страница с QR
- https://ВАШ_ЛОГИН.github.io/samart-ar/viewer.html?id=1 — работа

QR на index.html сгенерируются уже под этот адрес — открой её на Pages-домене
и сохраняй коды на печать оттуда.

Обновление контента (новые модели, правки описаний):
`git add -A && git commit -m "..." && git push` — Pages пересоберётся сам.

Нюансы:
- Бесплатный Pages работает только с публичным репозиторием (или GitHub Pro).
- Лимит размера репозитория — мягкий 1 ГБ; отдельный файл до 100 МБ.
  С оптимизированными GLB по 5–10 МБ места хватит на десятки работ.
- HTTPS включён по умолчанию — AR-кнопка и все браузерные API работают сразу.
